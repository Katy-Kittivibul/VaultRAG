## Objective
Designed and implemented an automated evaluation pipeline to audit and optimize a Retrieval-Augmented Generation (RAG) system querying a personal Obsidian vault. The framework addresses technical bottlenecks including library conflicts (RAGAS and langchain-google-genai incompatibility), API rate/quota limitations under free-tier models, and silent metric failures (NaN evaluation scores). By comparing a standard Cosine Vector Retriever against a Hybrid (Ensemble BM25 + Cosine) Retriever, the project establishes a robust methodology for measuring retrieval quality and generation correctness.

## Key Metrics
- **Retriever Performance Comparison (Mean Scores):**
  - **Cosine Retriever:**
    - Faithfulness: 0.9167
    - Answer Relevancy: 0.5941
    - Context Recall: 0.4583
    - Factual Correctness: 0.4233
  - **Hybrid (Ensemble BM25 + Cosine) Retriever:**
    - Factual Correctness: 0.5767 (up +15.34% from Cosine)
    - Answer Relevancy: 0.6186 (up +2.45% from Cosine)
    - Context Recall: 0.4583 (identical)
    - Faithfulness: 0.6786
- **Optimization & Ingestion:**
  - Semantic Cache Threshold: Cosine similarity >= 0.92
  - Vault Statistics: 76 Files, 178 processed chunks
  - API Savings: Switched to local Mistral 7B (Ollama) as judge and MiniLM-L6-v2 embeddings, halving remote API quota consumption and resolving RPM/RPD ceiling bottlenecks.

## Quick summary of what you did
- **Infrastructure & Ingestion:** Designed an ingestion pipeline utilizing `RecursiveCharacterTextSplitter` to chunk 76 markdown files from the Obsidian vault into 178 overlapping passages (chunk size 512, overlap 50), writing them into a local `Chroma` database vector store.
- **RAG Pipeline Engineering:** Built a standard semantic retriever using Chroma and a Hybrid Retriever using `EnsembleRetriever` with balanced weights (0.5 BM25, 0.5 Chroma Vector Search) powered by LangChain.
- **Evaluation Engineering:** Integrated the `RAGAS` framework utilizing a local Mistral 7B LLM (via Ollama) as the judge and `all-MiniLM-L6-v2` for embeddings. Implemented custom `_reground_references` logic to mitigate NaN failures and ground references directly in actual retrieved context.
- **Optimization:** Developed a `SemanticCache` layer with an embedding-based cosine similarity threshold of 0.92 to store queries and answers, preventing redundant LLM requests.
- **User Interface:** Constructed an interactive `Streamlit` dashboard (`src/dashboard.py`) to visualize mean evaluation metrics, compare source documents between retrievers, and inspect raw results.
